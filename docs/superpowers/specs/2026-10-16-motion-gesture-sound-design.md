# Motion, gesture, haptics and sound — design

Date: 2026-10-16
Status: approved in brainstorming, awaiting spec review

## Goal

Give the Claritel Agent app a consistent, calm, native-feeling feedback layer: motion, gestures, haptics and UI sound. The app is a work tool used on live calls, so feedback must confirm actions without distracting the agent or interfering with call audio.

## Decisions

- **Layers:** motion, gestures, haptics and sound.
- **Feel:** calm and native. Quick, lightly damped springs, subtle scale on press, short quiet sounds. No celebratory effects.
- **Native dependencies allowed:** `react-native-reanimated`, `react-native-gesture-handler`, `expo-audio`, installed with `npx expo install` for SDK 57-compatible versions. Check API details against the SDK 57 docs at implementation time, as `AGENTS.md` requires.
- **Controls:** two new settings, `uiSounds` and `haptics`, both default `true`. UI sounds follow the device silent switch. Motion follows the OS Reduce Motion setting.
- **Sound assets:** synthesized placeholders generated by a script in the repo, with no licensing issues. Branded files can replace them later under the same names.
- **Approach:** a central semantic feedback module plus in-house Reanimated/Gesture Handler primitives. No `@gorhom/bottom-sheet` or Moti.

## Architecture

```
src/feedback/
  events.ts      // FeedbackEvent union + table: event -> { haptic?, sound?, critical? }
  haptics.ts     // wraps expo-haptics: selection | light | medium | success | warning | error
  sounds.ts      // expo-audio players preloaded once at startup; play(name)
  index.ts       // feedback(event): applies gating, then calls haptics/sounds
src/theme/motion.ts         // durations, springs, easing tokens
src/components/motion/
  PressableScale.tsx        // press-in scale 0.97 + optional feedback event
  AnimatedSheet.tsx         // sheet that springs in and drags down to dismiss
  SwipeRow.tsx              // generic swipe row: left/right actions, threshold haptic
  SlideToAnswer.tsx         // incoming-call slide control
  FadeInList.tsx            // helpers for Reanimated entering/exiting/layout on list items
scripts/generate-sounds.ts  // synthesizes WAVs into assets/sounds/
assets/sounds/*.wav
```

### Motion tokens (`theme/motion.ts`)

- Durations: `fast` 150 ms, `base` 220 ms, `slow` 320 ms.
- Springs: `snappy` (press, chips, toggles) and `gentle` (sheets, layout). Both critically damped or close to it, so there is no visible bounce beyond a slight settle.
- Easing: standard ease-out for enters, ease-in for exits.

### Feedback gating (`feedback(event)`)

1. If `settings.haptics` is on and the platform is not web, play the event's haptic.
2. If `settings.uiSounds` is on, the event has a sound, and either no call is live (`useCall.getState().call` is null) or the event is marked `critical`, play the sound.
3. Sounds use an audio mode that respects the silent switch. They must not take over or duck call audio.
4. All calls are fire-and-forget. Errors are swallowed and logged once in dev only.

The existing `tap()` in `src/components/ui.tsx` stays as a thin wrapper over `haptics.ts`, which also respects `settings.haptics`. Callers move to `feedback()` as their screens are touched.

### Reduce Motion

A `useReducedMotion` hook (Reanimated's, or `AccessibilityInfo`) drives the primitives. When it is on, springs become `fast` (150 ms) timed transitions; fades are kept, and looping animations (the incoming-call pulse and button breathe) are static. Haptics and sound are unaffected.

## Events and sounds

| Event | Haptic | Sound | Critical (plays during a live call) |
|---|---|---|---|
| `press` | light | — | — |
| `select` (chip, tab, segmented) | selection | — | — |
| `toggle` (mute, hold, speaker) | light | — | — |
| `dial.key` | selection | `dtmf_<key>` | yes |
| `swipe.threshold` | light | — | — |
| `sheet.snap` | light | — | — |
| `status.changed` | medium | — | — |
| `call.answered` | success | — | — |
| `call.connected` | — | `connect` | yes |
| `call.ended` | medium | `end` | yes |
| `disposition.saved` | success | `saved` | — |
| `task.completed` | success | `complete` | — |
| `toast.success` | success | — | — |
| `toast.warning` | warning | — | — |
| `toast.error` | error | `error` | — |

Sound files (17): `dtmf_0`–`dtmf_9`, `dtmf_star`, `dtmf_hash` (standard DTMF dual tones, 120 ms), plus `connect`, `end`, `saved`, `complete`, `error`. Each is under 300 ms, has short fades to avoid clicks, and is normalised to about -18 LUFS. Ringtone and call audio are out of scope (see below).

## Changes on each screen

| Where | Motion | Gesture | Feedback events |
|---|---|---|---|
| Incoming call (`app/call/incoming.tsx`) | Avatar ripple moves to Reanimated; Answer/Decline buttons breathe gently | `SlideToAnswer`, with the existing tap buttons kept | `swipe.threshold` while sliding, `call.answered` |
| Active call (`app/call/active.tsx`) | Timer digits roll; controls use `PressableScale`; mute/hold icons cross-fade between states; network indicator cross-fades | Contact/notes sheet drags up and down | `toggle`, `call.connected`, `call.ended` |
| Dialer (`app/(tabs)/dialer.tsx`) | Keys press-scale; digits enter with a small pop; backspace collapses digits | Long-press backspace clears all | `dial.key` |
| Wrap-up (`app/call/wrap-up.tsx`) | Chips spring when selected; conditional fields expand and collapse with a layout animation; the selected chip's check icon zooms in | — | `select`, `disposition.saved` |
| Calls list (`components/CallRow.tsx`) | Rows fade in on mount and animate out on removal | `SwipeRow` replaces PanResponder (right: call back, left: disposition) | `swipe.threshold` |
| Tasks list (`components/TaskRow.tsx`, `app/(tabs)/tasks.tsx`) | Same as the calls list (fade in/out; virtualized lists don't re-flow) | `SwipeRow` (right: complete, left: snooze) | `swipe.threshold`, `task.completed` |
| Status pill (`components/TopBar.tsx`) | Colour and width animate between statuses; timer digits roll | — | `status.changed` |
| Sheets (`components/Sheet.tsx`, `StatusSheet.tsx`) | `AnimatedSheet` springs in; backdrop fades | Drag down to dismiss, with rubber-band resistance past the top | `sheet.snap` |
| Toasts and dialogs (`components/feedback.tsx`) | Toasts slide and fade in; dialogs fade and scale in | Swipe a toast away | `toast.*` |
| Tabs (`app/(tabs)/_layout.tsx`) | Active tab icon gets a small scale bump | — | `select` |

`Sheet` keeps its current props (`open`, `onClose`, `title`, `footer`, `scroll`), so no call sites change. Under the hood it renders `AnimatedSheet` instead of `Modal animationType="slide"`, and keeps keyboard avoidance and safe-area padding.

## Root setup

- Wrap the app in `GestureHandlerRootView` in `src/app/_layout.tsx`.
- Preload sounds once after fonts load. If preloading fails, the app still renders.
- Add the Reanimated config if the SDK 57 docs require it (Babel plugin or worklets setup). Expo's default config may already cover it; check before adding anything.

## Settings

- `src/store/settings.ts`: add `uiSounds: boolean` and `haptics: boolean`, both default `true`. They are persisted with the existing store.
- `src/app/settings.tsx`: add a "UI sounds" and a "Haptics" toggle to the audio section.

## Errors and accessibility

- A sound failing to load or play is skipped silently. Haptic failures are ignored. Neither may throw into render or the call state machine.
- Every gesture has a non-gesture alternative. Answer/Decline buttons stay on the incoming screen, and swipe rows expose `accessibilityActions` matching their swipe actions.
- Animations are presentation only. `callStore` stays the source of truth, and gesture completion calls the same store actions the buttons call.
- Keep tap targets at 48 dp minimum. Press-scale must not shrink the hit area.

## Testing

- `npx tsc --noEmit` and `npx expo lint` pass.
- Unit tests for `feedback()` gating: haptics off, sounds off, live call with critical and non-critical events, web. This adds a minimal Jest setup (`jest-expo`) if none exists.
- Web preview: check sheet drag, swipe rows, press feedback, list animations and sounds in the browser pane.
- On device: haptics and gesture feel can only be confirmed in a development build (`npx expo run:android` or `eas build --profile development`). Report this as unverified until it has been run on a device.

## Rollout order

1. Dependencies, `GestureHandlerRootView`, motion tokens, the feedback module, settings toggles, and `tap()` rewired to respect settings.
2. Sound generation script and assets, plus preloading.
3. Primitives: `PressableScale`, `AnimatedSheet` (with `Sheet` moved onto it), `SwipeRow`, `FadeInList`, `SlideToAnswer`.
4. Call flow: incoming, active, wrap-up, dialer.
5. Lists, status pill, toasts and dialogs, tabs.

Each step leaves the app building and usable.

## Out of scope

- Real ringtone, call audio routing and the CallKit/ConnectionService integration (already tracked in the README).
- Branded sound design (the placeholders are replaceable).
- Celebratory effects such as confetti.
